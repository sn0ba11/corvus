## Licence and attribution conclusions

- The original Workbench orchestrator/application code is licensed under PolyForm Noncommercial 1.0.0. Independently deployed third-party tools retain their own licences; their notices and relevant source-offer obligations must accompany redistributed images. Corvus's PolyForm licence does not relicense third-party tools or override upstream rights and obligations.
- GPL-2.0-only, GPL-3.0-only and AGPL-3.0-or-later works are not combined into the application. They run as independent executables in independent containers over narrow HTTP/job boundaries. Any redistributed images still require their own complete corresponding-source and notice compliance. The SearXNG derivative image preserves the official source identity and exact upstream revision.
- Blackbird currently has no grant to redistribute. The development Compose file performs a local clone/build from the official repository, but production installers must leave it disabled unless legal permission or an upstream licence appears. This is a release blocker for advertising a bundled Blackbird image, not a reason to mislabel it.
- WhatsMyName data is CC-BY-SA-4.0. If later shipped, retain attribution, licence, modification notices and ShareAlike terms for the dataset.
- Bellingcat Name Variant Search and Auto Archiver are MIT-licensed. Their identities and selected revisions are recorded in `THIRD_PARTY_NOTICES.md` and `upstreams.lock.json`.
- The Internet Archive CDX implementation/source identity is recorded for reproducibility, but Workbench only consumes public metadata from the deployed service and does not bundle its source.
- Photon and Datasploit are GPL-3.0 technique references only. Corvus does not import, vendor, execute or redistribute their source; the live-site crawler and domain-RDAP implementation are independent native code with narrower collection boundaries.
- No upstream generative-AI feature is enabled. Investigation identifiers are never sent to AI services. Local YuNet/SFace face matching is an opt-in biometric similarity aid, and every candidate remains subject to explicit analyst review.
- No upstream updates occur during application runs. Updating means reviewing and changing `upstreams.lock.json`, rebuilding, testing and recording a release.

## Pinned-commit packaging workarounds

- Corvus uses the locally built Naminter runner for JSON output. The runner excludes the upstream PDF renderer and uses the pinned WhatsMyName dataset. This does not affect Corvus case or evidence exports.
- The locally built yt-dlp runner excludes the Shahid extractor because the selected upstream revision embeds a service credential in that module. Shahid-specific extraction is unavailable.
- Maigret can save its site database at shutdown even with startup auto-updates disabled. The adapter uses the documented `--db` option with a per-job writable copy of the pinned `/opt/tool/maigret/resources/data.json`; no network update or installed-file write is permitted.
- Blackbird resolves its results directory relative to its source tree, which is read-only at runtime. The pinned source receives a narrowly scoped build-time patch that honours `BLACKBIRD_RESULTS_DIR`; the runner sets that variable to the current per-job `/output/<uuid>` directory. The patch script fails the image build if the selected upstream source no longer matches the reviewed code block.
- Holehe at the selected commit imports `requests` from its Facebook module without declaring it in installed runtime dependencies. The isolated image adds `requests==2.34.2`; the initial `ModuleNotFoundError` is retained as the regression rationale.
- theHarvester creates `~/.theHarvester` on first execution. The runner recreates its non-root home inside the hardened `/tmp` tmpfs before its health probe and every application run uses that private home.
- Subfinder is compiled from the pinned Git commit in a Go builder stage and copied as a static executable into the standard non-root Python runner image. The runtime receives no provider API keys by default, writes only case-scoped JSONL, and the adapter rejects records outside the queried domain boundary.
- The name-variant implementation uses the public Bellingcat variation categories but does not embed or invoke the npm package at runtime. Auto Archiver is likewise not bundled into the Workbench stack; the examiner receives a pinned requirements file, bounded configuration, URL CSV, provenance manifest and SHA-256 checksums for explicit execution in a separate environment.
- Bing full-name collection uses the public RSS rendering endpoint only in the explicitly documented personal/non-commercial mode requested for this deployment. It issues five bounded query groups, follows no redirect, rejects private/internal result URLs, stores the returned XML and never uses an undocumented browser scraper or paid API credential.
- SearXNG is bundled as a private free fallback because Bing RSS can return unrelated result sets. It runs five bounded deterministic name queries, retains source-engine failures and per-query JSON, rejects private/internal URLs and applies the same subject-name relevance guard before a result can enter the evidence register. No API key, subscription or metered search service is configured.
- Automatic Wayback discovery retains the public first capture, latest materially distinct capture and at most 50 digest-collapsed CDX records for each of at most ten eligible findings. The report warns that the earliest capture is not a page-creation date.
- Historical domain URL discovery remains passive and source-specific: Common Crawl, AlienVault OTX and optional URLScan records are canonicalised into normal evidence while retaining source timestamps/scan identifiers. URLScan performs search only and never submits the investigated domain for a new scan.
- SpiderFoot-derived work is intentionally modular. The current selection excludes network scanning, vulnerability checks, dark-web/breach sources, recursive spiders and a generic run-all-modules control from the person-search workflow.

The exact machine-readable record is `upstreams.lock.json`. Copyright remains with each upstream author/contributor.

## Enabling Blackbird

Blackbird is excluded from the default build and the Corvus release assets. A user who has independently obtained a compatible copy may run the local recipe for their own permitted use.

```sh
docker compose --profile blackbird up -d --build blackbird
```

Alternatively set `OSINT_RUNNER_BLACKBIRD_URL` in the Compose `.env` to a compatible runner on a network accessible to the app, and recreate the app container. Choose Blackbird in the case only after the runner is healthy. Collector requests send the selected case query to the configured tool and the tool's upstream sites.

GHunt is tracked as an upstream reference. The current Corvus build has no GHunt runner or authenticated Google-session setup. Run GHunt independently under its own terms. Selected public result URLs can be entered through the case’s Search queries import with analyst notes. Keep GHunt session files and raw credential material outside Corvus.

Image builds acquire upstream code, models and dependencies on the user's system. Public Corvus release assets contain Corvus source and launchers. They exclude prebuilt tool images and offline image bundles. Keep the upstream licence and copyright notices with any separately redistributed copies. GPL distributors must satisfy corresponding-source obligations, AGPL services can also have a network source-offer obligation, and redistributed WhatsMyName adaptations retain CC BY-SA attribution and share-alike terms.
